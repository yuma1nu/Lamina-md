## 4. 受け入れシナリオ

### 記録を続ける

- 月末の記録があるテーマで翌月の「今日へ」を実行すると、月次ファイルと今日の見出しが1回だけ作られる。
- 過去月を修正しても、その月だけのMarkdownが更新される。
- 左右で同じテーマを開き、片方の修正がもう片方へ反映される。カーソルとスクロールは独立する。
- 自動保存に成功している間は状態通知を出さない。失敗した場合は編集内容を保持し、再試行できる。
- 終了・再起動で、タブ・ピン留め・左右分割・作業位置を復元できる。

### 記録から知識を切り出す

- メモをフォルダーへドラッグで整理し、平置きへ戻せる。フォルダー内でメモ・子フォルダーを直接作成できる。
- フォルダーごとの移動でも参照リンク・画像・タブを維持し、同名衝突・自己配下への移動・保存失敗で元の本文を失わない。
- 選択部分をメモへ切り出すと、新規メモへ本文が移り、元の位置にリンクが残る。
- 通常タブのクリックは現在のタブで移動し、ピン留めタブからは別タブへ開く。
- 明示的な新規タブ・右ペインへの操作を選べる。
- ファイル名変更で通常のリンク表示も変わり、指定した別名は維持される。
- コードブロック内に同じ文字列があっても、リンク修正で書き換えられない。

### 画像で説明する

- スクリーンショットの貼り付け後、本文内で比率を保ってサイズ変更できる。
- 画像から注釈モーダルを開き、図形・文字を編集して完了すると本文へ戻る。
- キャンセルでは注釈の今回の変更が残らない。
- アプリ再起動後も丸や矢印、文字を個別に再編集できる。
- Windowsの表示倍率や編集画面のズームを変えても、注釈の位置がずれない。

### 資料を貼り付けて再利用する

- 引用符付きローカルパス、UNC、SharePointのコピーURLから登録でき、追加入力なしで確定できる。
- 新規テーマ内の登録ではそのテーマが選択され、既存資料では既存テーマに今回のテーマが重複なく加わる。
- 未指定テーマ、空のメモ、空の本文でも登録できる。
- 同じURLの再利用では「登録済み」と表示され、初回登録日は変わらない。
- ファイル名情報が取得できた場合は拡張子付きの名前をリンク表示に使う。
- 本文リンクには種類アイコンが付き、1クリックで資料本体が開く。情報アイコンからはプロパティが開く。
- 一覧で種類・追加日・メモ・テーマなどを扱い、フィルタして編集した内容がMarkdownにも保存される。
- パス修正・マージで参照元リンクが更新され、短いメモと詳細本文が失われない。
- 別のMarkdownエディタでも、YAMLと本文、元資料のリンクを確認できる。

### 探して移動する

- 「温度」のような2文字の日本語、英数字、記号を含む語で検索できる。
- 検索結果にテーマと日付、抜粋が表示され、正しい位置へ移動できる。
- 資料のバックリンクに実際の参照行の周辺文章が表示される。
- 終了中にテーマフォルダを移動しても、別テーマの同名月次ファイルへ誤接続しない。
- 終了中の名前変更による未解決リンクを、存在するリンクとして表示しない。

### PDFを更新する

- 月次ファイルと通常メモの全文が、A4縦・タイトル・ページ番号付きで出力される。
- 日本語本文を検索・コピーでき、注釈入り画像、数式、コード、外部リンクを確認できる。
- 1時間経過または通常終了で、変更された対象だけを生成する。
- 過去月の修正、注釈更新、画像サイズ変更も反映される。
- 出力中の追加編集が次回の更新対象に残る。
- 出力先でPDFが使用中などの失敗があっても、元のMarkdownと前回の正常なPDFを保持し、次回も再出力できる。

## 5. 確認の方法

| 対象 | 方法 |
| --- | --- |
| 月別区間・日付・リンク解析・パス変換・YAML・出力更新判定 | 入出力の意味を確認するTypeScript単体テスト。日本語、改行、空白、括弧、同名を含める。 |
| ファイル保存・移動・複数ファイル操作・回復 | Rustの一時保管庫を使う統合テスト。古いリビジョン、失敗、途中終了を含める。 |
| タブ・分割・資料登録・注釈モーダル | 実TauriアプリのWindows E2E。ブラウザ上だけの成功を実機成功の代わりにしない。 |
| 日本語IME・クリップボード形式・表示倍率 | Windows上での手動確認を必須とし、可能な部分のみ自動化する。 |
| PDF | テキスト抽出による検証と目視確認。自動生成・終了待機はネイティブ環境で確認。 |
| 品質 | 型検査、lint、フロントエンドのビルド、Rustのチェックとビルド。ライブラリ採用後に必要なコマンドを定義。 |

TauriはWebDriver経由のE2Eを提供するため、Windowsではその経路を候補にする。テストツールとWebView2の対応バージョンは導入時に確認する。[Tauriのテスト](https://v2.tauri.app/develop/tests/)

見た目だけの小さな変更やライブラリ内部の挙動をなぞるためのテストは増やさず、保存・編集・参照・再起動など、壊れると日常利用に影響する振る舞いを中心に確認する。

## 6. 設計中の細部の扱い

入力感や保存形式に関わる方式はM0で検証し、詳細を実装設計に追記する。ユーザーの作業方法を変えない内部の選択は、実装側で合理的な既定値を選ぶ。

画像サイズの保存構文、終了中の移動の対応条件、資料ページのPDF対象、削除した元ノートのPDFの扱いなど、利用者から見える要件を変える場合は、具体的な選択肢と影響を示して確認する。細部の未決定を理由に、独立して進められる基盤作業を止めない。

## 7. 完成として扱う条件

- 仕様書の確定要件が、サンプル表示だけでなく実際のファイル操作として動く。
- 主要シナリオがWindowsの実行ファイルで通り、検証できた項目と未検証項目が区別されている。
- 保存失敗・参照先なし・再起動・通常終了時にも、本文と資料情報を失わない。
- ダークモード、アイコン、文字、余白、モーダルと一覧の操作が統一されている。
- 日本語入力と連続したメモ取りを妨げる不具合が残っていない。
- 確認が必要な未実装箇所を、動いているように見せる代替表示で隠していない。

自動更新や一般配布のためのインストーラーは、現時点の初期版完成条件には含めない。
