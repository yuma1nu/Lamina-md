# 日常利用の品質改善

更新日：2026-11-17

## 実装した内容

1. 本文を16px、ナビゲーション・タブ・入力欄を主に13px、補足を12pxへ調整。本文の行間は1.8とし、タイトルと本文上部の余白を縮小した。
2. ダーク配色の補足文字を明るくし、選択中の項目・タブ・検索結果・キーボードフォーカスを明確化。本文を白一色にせず、情報の強弱は維持する。
3. Undo／Redo履歴を画面から独立して保持する。起動中のタブ切替と閉じて再開する操作が対象。保管庫・ペイン・文書・本文編集形式を分け、原文が変わった場合は古い履歴を採用しない。再起動後のUndo復元は行わない。
4. 左右サイドバーと左右ペインの境界をドラッグ・矢印キーで調整可能にした。ダブルクリックまたはHomeで初期値へ戻る。幅と比率は保管庫ごとに保存する。1100px以下では右サイドバーを必要時に開き、本文を常時覆わない。
5. タブ・情報・折り畳み等の操作範囲を拡張。未ピン留めのピン操作はホバー／キーボードフォーカス時に表示する。資料一覧のプロパティ編集は鉛筆アイコンとし、情報アイコンの詳細表示と区別する。
6. 資料一覧の検索・フィルタ・並べ替え・選択・チェック・縦横スクロール位置、フォルダーの開閉を保存。ノート移動時には対応する画面状態のパスも更新する。検索結果は上下キー・Enterで開ける。
7. 文書結合結果、リンク解析、バックリンク、検索結果を再利用する。同じ行内のカーソル移動ではプレビューを再構築せず、別月への移動でも変化しない月の装飾を再利用する。画像はキャレット移動だけで再解析せず、見出しの折り畳みボタンも必要時だけ更新する。入力時のフォルダーツリー再描画を抑える。
8. 資料のメモを複数行で表示・編集可能にし、日付は非編集中にYYYY-MM-DDで表示。ネイティブカレンダーは維持する。バックリンクの抜粋はリンク名で表示し、参照行を強調する。検索語も強調する。抜粋中のHTMLやリンクは実行しない。
9. エラーの再試行を失敗した操作に合わせる。ノート保存失敗では入力保持と保存再試行を案内し、リンク起動失敗ではリンクの再試行を表示する。Office資料ではブラウザを明示的に選べる。別のリンクを開いても保存失敗の通知を消さない。通常の保存状況は表示しない。

## 保存と性能上の境界

画面状態は既存の`.lamina/workspace.json`へ任意の`preferences`として保存する。形式バージョンは1を維持し、旧データは既定値で開く。不正な幅・比率・検索条件等は検証する。本文のMarkdownへアプリ固有の情報を書き込まない。

編集履歴はCodeMirrorのhistoryフィールドだけを保持し、破棄した画面やコールバックを保存しない。直近60件を上限とし、異なる原文に過去のUndoを適用しない。

復帰時はファイル名・サイズ・更新時刻から保管庫の変更を先に調べ、変化がなければ全文を読み込まない。ファイル監視からの通知と手動再読み込みはこの省略を使わない。本文読み込みの前後でメタデータが変わった場合は省略用の値を採用しない。更新時刻とサイズを意図的に維持した変更が監視通知も届かない場合、復帰時の確認だけでは検出できないため手動再読み込みが必要。保存時のリビジョン照合は維持する。

## 検証

- 履歴の復元・原文変更時の破棄、旧セッションの互換性、不正な設定値、プレビューの再利用、抜粋の変換を単体テストで確認する。
- ブラウザでタブ切替後のUndo／Redo、外部変更後のUndo、箇条書き・タスクの連続編集、資料一覧とフォルダーの復元、縦横スクロール、境界のドラッグ・キー操作、検索、失敗時の再試行を確認する。
- 1280×860の画面に対して100・125・150％表示相当のCSSビューポートとdeviceScaleFactorで文字サイズ・操作範囲・配置を確認する。Windowsの実際のDPI設定を切り替える検証とは区別する。
- Rustで軽量な変更確認が書き込み・移動・空フォルダーの追加を検出することを確認する。

性能テストは24か月、300メモ、480画像参照を使う。時刻モックと操作ごとのDOMトレースを無効にし、操作開始から次の描画フレームまでをホストの実時間で測定する。DOMトレースの全文走査が計測値を押し上げるため、通常の回帰テストと分けて単独で実行する。

```powershell
node scripts/test-browser.mjs --workers=4 --grep-invert '日常性能'
node scripts/test-browser.mjs --workers=1 --grep '日常性能'
```

Chromiumの開発ビルド・代替IPCを使った計測では、上下移動の95％値は約25ms、入力は約44msだった。ブラウザ自動操作の通信・フレーム待ちも含み、Windows実機やファイルサーバでの性能保証値ではない。個別の計測結果とCPUプロファイルは性能テストの添付へ出力する。

読みやすさの基準は[W3Cの文字コントラスト](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)と[操作対象のサイズ](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)を参考にする。アプリ全体のWCAG適合を宣言するものではない。
