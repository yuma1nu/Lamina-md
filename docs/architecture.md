# Lamina.md 実装設計

更新日：2026-11-12

[初期版仕様](specification.md)を実現するための実装方針。ユーザーと合意した利用要件は仕様書を正とし、本書の内部構成・ライブラリは実機検証に応じて調整する。2026-11-12に初期実装へ着手。検証結果と実装状況はREADMEおよび開発計画に記録する。

## 1. 基本方針

- Markdown、YAML、画像、注釈JSONをユーザーデータの正本とする。
- 検索・バックリンクの索引は再構築可能にし、独自データベースだけに本文や資料プロパティを保存しない。
- 編集中の未保存データはドキュメント単位で共有する。画面やタブごとに別の本文を持たせない。
- ファイル操作はRust側に集約し、自動保存、外部変更検知、リンク更新、PDF生成の整合性を保つ。
- ダークモードの外観、IME、フォーカス、キーボード操作を最初の実装から揃える。
- 最初から実際のTauriアプリとして実装し、月またぎ編集・注釈・PDFの技術検証も、その後使い続ける部品の中で行う。

## 2. 推奨する技術構成

| 対象 | 構成案 | 選定理由・確認事項 |
| --- | --- | --- |
| デスクトップ | Tauri 2、Rust、Windows WebView2 | 指定の構成を採用。ネイティブ保存・外部ファイル起動・PDF生成を担当。 |
| フロントエンド | React、TypeScript、Vite | 画面と業務ロジックを分離し、型検査を有効にする。正確なバージョンは実装開始時に互換性を確認して固定。 |
| 本文編集 | CodeMirror 6 | Markdownのテキストを維持し、装飾・画像などを表示する。ライブプレビュー自体はアプリ側の拡張として実装する。 |
| Markdown処理 | 現在はCodeMirrorのCommonMark構文木、Wikilink拡張 | 本文中の位置を保ってリンク・日付見出しを解析。画像・数式・PDFの共通解析とWeb Worker化は後続で検討。 |
| 数式 | [KaTeX](https://katex.org/docs/options) | 編集中とPDF用HTMLで同じ数式描画を使う。 |
| UI部品 | Radix Primitives、独自CSS | モーダル・メニューのフォーカスやキーボード動作を基盤として使い、見た目を統一する。 |
| アイコン | [lucide-react](https://lucide.dev/guide/react/) | アイコンの線幅・サイズを統一。装飾のための多色化はしない。 |
| 画面状態 | [Zustand](https://zustand.docs.pmnd.rs/learn/getting-started/introduction) | タブ・分割・モーダルなどを管理。本文とUndo履歴はCodeMirror側で管理する。 |
| 資料一覧 | TanStack Table | ソート・フィルタ・選択を利用。セルの編集UIと保存処理はアプリ側で作る。 |
| YAML | `yaml`パッケージのDocument API | 不明なプロパティやコメントを保持しながら既知の値を変更する。 |
| 画像注釈 | Konva 10.9.1＋react-konva 19.3.2を採用 | 図形操作・Transformerを使い、モーダル・HTMLテキスト入力・操作単位の履歴を実装。 |
| 検索・参照索引 | 現在はTypeScriptのメモリー上の索引 | 未保存本文を重ねる。資料一覧・大規模保管庫ではSQLiteとRust側の[rusqlite](https://github.com/rusqlite/rusqlite)を候補にし、本文の正本にはしない。 |
| 外部変更監視 | Rustのnotify 8.2.1 | Markdownとディレクトリーの変更を再走査の手掛かりにする。 |
| PDF | WebView2のPrintToPdfをRustから利用 | 印刷用HTMLを、操作画面とは別の非表示WebViewで出力する。実機検証が必要。 |

CodeMirrorには装飾と分割ビューの実装例がある。単純に導入すれば要求するライブプレビューが完成するわけではなく、入力中の表示切り替えとIMEの調整が必要。[装飾の公式例](https://codemirror.net/examples/decoration/)、[分割ビューの公式例](https://codemirror.net/examples/split/)

Radixはモーダル内のフォーカス管理などを提供し、TanStack Tableは描画を持たない一覧制御ライブラリである。どちらもアプリの見た目と保存処理は独自に組み立てる。[Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog)、[TanStack Table](https://tanstack.com/table/latest/docs/framework/react/quick-start)

## 3. 責務の分離

### ReactとTypeScript

- アプリの外枠、テーマ・メモ一覧、タブ、分割、資料一覧、右パネル。
- CodeMirrorを使った入力、ライブプレビュー、選択とUndo。
- 日付見出しやリンクの解析、資料YAMLの読み書き、変更箇所の計算。
- 注釈の編集と画像の合成。
- 表示用HTMLと印刷用HTMLの構築。

### RustとTauri

- 保管庫の走査、ファイル読み込み、保存、移動、名前変更。
- ファイル変更の監視と再走査、外部変更の検出。
- 保存時のバージョン照合、複数ファイル操作の記録と回復。
- Windowsクリップボードのファイル情報やパス形式の取得。
- ローカル・UNC・Webリンクの起動。
- SQLite索引、PDFキュー、終了処理。

### 両者の境界

ファイル読み込み結果は本文・パス・リビジョンを返す。書き込みは「対象パス・読み込み時のリビジョン・新しい内容」を渡し、古い内容をもとにした保存を検出する。リビジョンは内容ハッシュなどの内部情報とし、Markdownには保存しない。

Markdown解析の結果にも元のリビジョンを付ける。Rustは、現在のファイルと一致する解析結果だけを索引へ反映する。保存の完了を索引処理の完了待ちにしない。

位置はTypeScript内ではUTF-16オフセット、ディスク内容の照合はバイト列のハッシュとする。Rust側でUTF-16位置をそのままUTF-8バイト位置として使わない。

## 4. ドキュメントと月またぎ編集

### モデル

| モデル | 主な情報 |
| --- | --- |
| Theme | テーマのフォルダパス、表示名、月別ファイル一覧 |
| Document | 論理上の編集対象、本文状態、リビジョン、未保存状態 |
| MonthSegment | 対象年月、物理ファイルパス、論理本文上の範囲、改行・末尾の情報 |
| Pane | 開いているタブ、アクティブなタブ、スクロールと選択位置 |
| Tab | 開く対象、ピン留め状態。本文はDocumentを参照する |
| Material | 資料Markdownのパス、既知のYAML項目、未知の項目、本文 |
| Reference | 参照元パス、位置、日付見出し、参照先、表示名、周辺文章 |

### 編集方式

1テーマを、月別ファイルを結合した1つの論理ドキュメントとしてCodeMirrorに渡す方式を第一案とする。月ラベルやファイル境界は編集データに混ぜず、装飾として表示する。

論理位置とMonthSegmentの対応を管理し、編集された範囲に対応する月だけを保存する。表示のために補う改行が必要な場合も、補助領域として明示的に管理し、元ファイルへ混入させない。変更していない月を再整形・再保存しない。

月境界をまたぐ選択・削除・貼り付け・Undoを最初の技術検証に含める。境界を削除しただけで月次ファイルが1つに結合されたり、別月の内容として保存されたりしないことを採用条件にする。この対応が安定しない場合は、本格的に機能を積み上げる前に編集方式を見直す。

表示はCodeMirrorの可視領域を中心に描画し、画像と装飾の生成を制限する。開いたテーマのテキスト自体は当初まとめて読み込み、任意の範囲だけを読み込む複雑な実装は計測結果に応じて追加する。

同じドキュメントを左右で開く場合は変更トランザクションを共有し、選択位置とスクロールはペインごとに管理する。React再描画ごとにエディタを作り直さない。

### ライブプレビュー（現在の実装）

CodeMirrorのStateFieldへ物理ファイルのソースを保持し、各トランザクションで更新する。React側のモデル同期は専用のStateEffectで置き換え、エディタ側の解析・入力補完とファイル境界を一致させる。

CommonMarkの構文木をファイルごとに解析し、見出し、太字、斜体、インラインコード、引用、コードブロック、通常・参照形式・自動リンクをDecorationで表示する。同じ内容のファイルの構文木は再利用する。記法の非表示は本文を変更せず、選択がある行では記法を表示する。コードブロックは内部のいずれかの行を編集している間、開始・終了フェンスも表示する。前月の未完了フェンスやリンク定義を翌月へ持ち越さない。Enter／BackspaceのMarkdown補完も物理ファイル内で実行して論理位置へ変換する。

エディタの行要素には縦マージンを使わず、見出しの余白はpaddingで確保する。H1は上18px、H2は上15px、ほかは上9px、下は4px。marginを使うとCodeMirrorの行高さに余白が含まれず、見出しが増えるほど座標がずれ、上下キーやクリックの移動先が誤るためである。

月区切りのブロックWidgetも、上5px・下22pxの余白を外側のpaddingに含める。内側のラベルに上13px・下8pxのpaddingと下線を置き、縦マージンで計測範囲外の余白を作らない。先頭の月ラベルと途中のファイル境界の両方に同じ構造を使う。

箇条書きの点表示は元のListMarkを残すmark装飾とCSSで描き、Widgetへの置き換えやatomicRangesへの追加を行わない。編集中も同じ点表示・文字幅を維持し、装飾記号は読み上げ対象から外す。キャレットはdrawSelectionで描画し、折り返し境界での関連付けを含めて表示する。[CodeMirrorの選択・カーソルAPI](https://codemirror.net/docs/ref/#view.drawSelection)

task-list.tsのtaskMarkerで、実際のListMark直後のチェック記法だけを判定する。プレビューは行頭記法をmark装飾で透明にし、文字幅を維持したままゼロ幅Widgetからチェックボックスを重ねる。WidgetをatomicRangesには含めず、キャレット補正の範囲をチェック記法の直後まで延ばす。クリックはチェック欄の1文字だけを書き換え、Ctrl+Lは物理ファイルごとに構文木から対象行を選び、仮想区切りを編集せずに作成・切り替えを行う。コード・YAML・HTML・見出しを除き、タスク操作を独立したUndo履歴として扱う。

リスト行の字下げ・行頭記号・直後の空白を、物理ファイルごとの構文木からStateFieldへ格納する。transactionFilterで単一キャレットを本文先頭へ補正し、上下移動のgoalColumnを引き継ぐ。範囲選択は元の記法を含めて扱う。本文先頭での左キーは前の行末へ移し、月境界では仮想区切りへ入らず前の物理ファイル末尾へ戻す。初期選択の補正はEditorView生成前に行い、復元中のスクロール位置を編集位置として上書きしない。Tab／Shift+TabはListItemの親・前の兄弟・子孫を調べ、選択ブロックと継続文をまとめて動かす。通常本文・コードでは従来の行インデントへフォールバックする。

目次は本文のH1〜H6とSetext見出しを各ファイルの構文木から抽出する。YAML・コード・引用やリスト内は除外し、装飾・リンクの記法を除いた表示名と階層、物理ファイルと論理本文の位置を保持する。テーマ・メモ・資料ページで同じ規則を使う。変更のないファイルの抽出結果は再利用する。

改行などのリストコマンドは物理ファイル用の一時EditorStateで処理する。初期解析は先頭の約3,000文字に制限されるため、ensureSyntaxTreeで解析を完了し、空トランザクションで解析結果を状態へ反映してから標準のMarkdownコマンドを実行する。Enter補完が長文末尾で通常改行へ落ちることを防ぐ。Deleteの結合とAlt上下の並べ替えはListItemの構造を用い、前者は次の行頭を除去して子孫の字下げを調整、後者は兄弟ブロックを子孫・継続文ごと交換する。操作を独立した履歴として扱う。

formatting.tsは物理ファイルごとの完全な構文木から装飾範囲と保護領域を判定する。太字・斜体・取り消し線・インラインコードの追加／解除、リンク先選択、コードブロック、見出し・引用・リストの切り替えをまとめ、標準キーより高い優先順位で登録する。複数行は本文部分を行ごとに扱い、書式操作を独立したUndo履歴とする。リスト解除では子孫の字下げを調整し、最小限の差分を適用して本文中のキャレット位置を保持する。プレビューはGFMを含むmarkdownLanguageの構文木で取り消し線も判定し、水平線は元の行の高さを変えず描く。表など、構文解析できても専用表示のないものは未実装として点検一覧に残す。

heading-folding.tsは目次と共通の見出し抽出結果から、同階層以上の次の見出し直前／物理ファイル末尾までの範囲を作る。独自foldServiceとCodeMirrorのfoldStateで節を畳み、見出し左には高さを変えないインラインWidgetで開閉ボタンを置く。隠れた位置への選択は標準の折り畳み解除を使い、見出しを編集したときはtransactionExtenderで範囲を再検証する。画面状態のfoldsはファイル内の両端を保存し、現在の見出し範囲に一致するものだけ復元する。Markdownの本文は変更しない。

HTTP／HTTPSのリンクは、編集行以外では通常クリック、編集行ではCtrlクリック、いずれもホイールクリックで開く。Tauriの専用コマンドでURLを再検査し、[公式openerプラグイン](https://v2.tauri.app/plugin/opener/)から既定ブラウザーへ渡す。プラグインの自動リンク処理は無効にし、エディタの操作と二重に反応させない。ノートのWikilinkと通常のMarkdownリンクも本文内で移動できる。画像は独立したStateFieldのWidgetで表示する。任意のHTMLは実行せず、単独のimgタグのsrc・alt・widthだけを読み、独自DOMへ組み立てる。数式・表、言語別コードハイライトは未実装。資料リンクの登録・ローカル起動は下記の資料機能へ接続した。

### 作業状態の保存と復元（実装済みの範囲）

`.lamina/workspace.json`の形式バージョン1に、左右のタブと順序、ピン留め、アクティブなタブとペイン、分割・目次・サイドバーの表示状態を保存する。選択の両端は元ファイルのパスとファイル内の文字位置で保持し、過去月の長さが変わっても選択を復元できる。スクロール位置はペイン・タブ別のピクセル位置で保持し、表示幅や前方の内容が変わったときの完全な位置追従は今後の調整対象とする。

画面状態の変更は500ms後に専用の直列キューで保存し、通常終了・保管庫切り替え・`Ctrl+S`では本文の保存を待ってから画面状態を保存する。通常終了中は編集を止め、保存に失敗すれば編集可能な状態へ戻す。タブ切り替え時はDOMが外れる前に選択・スクロール位置を取得する。

起動時に前回の保管庫を開き、現在の走査結果に存在するノートだけを読み直す。読めないタブを通知して残りのタブを復元し、位置は現在のファイル長に収める。管理情報は同じフォルダの一時ファイルから置換する。JSON破損・未対応形式を上書きするときは元の管理ファイルを`workspace-recovered-*.json`へ退避する。本文ファイルには画面状態や識別IDを加えない。

### 日付

「今日へ」はWindowsのローカル日付を操作時に取得する。既存の日付を調べ、未作成の月次ファイルと見出しを同じ操作で作成する。日付変更だけを理由に既存本文を自動移動する機能は追加しない。

## 5. 保存・外部変更・回復

- 保存はドキュメントごとのキューで順序を保証し、新しい編集を古い保存完了で上書きしない。
- 自動保存の待ち時間は暫定500msを出発点に計測する。`Ctrl+S`、ドキュメントを閉じる操作、終了時は待ち時間を解除して保存する。
- 既存ファイルのBOM、改行、末尾改行を読み込み時に保持し、変更していない内容の不要な書き換えを避ける。新規ファイルの標準はUTF-8・LFとする実装案。
- 同じディレクトリ内に一時ファイルを書き、書き込み完了後に置換する。Windowsのファイル使用中・権限・同期中の失敗も処理する。
- 保存前に読み込み時の内容との相違を検出する。未保存の編集と外部編集が衝突した場合は、双方を保持して選択できる状態にし、無条件の上書きは行わない。
- ファイル監視は更新の手掛かりとし、起動時・ウィンドウ復帰時・必要時の再走査で取りこぼしを補う。自分の保存を外部編集と誤認しない。
- 一時ファイル、管理ファイル、PDF出力先を通常ノートとして取り込まない。
- 自動保存の成功表示は出さず、失敗時だけ対象と再試行の導線を表示する。

複数ファイルの移動、リンク修正、メモ切り出し、資料マージは単なる連続上書きにしない。`.lamina/operations/`に対象・変更前の内容・進行状況を記録し、途中終了時は完了または回復できるようにする。SQLiteのトランザクションだけでは、複数のMarkdown保存の一括成功は保証できない。

現在の移動・名前変更・切り出しは、全対象のリビジョンと衝突を事前検査し、`.lamina/operations/current.json`へ変更前後と移動先を記録して実行する。移動は一時パスを経由し、大文字小文字だけの変更にも対応する。完了記録前の中断は、次の保管庫読み込み時に元へ戻す。途中で別のアプリに変更された内容は上書きせず、記録を保持して失敗を通知する。資料マージは後続の対象。

監視イベントは350msでまとめ、自分の保存後と同じリビジョンなら再読込しない。管理用・一時ファイルは監視から除く。未保存の本文は先に通常の保存照合を行い、競合時は編集バッファを残して通知する。ウィンドウ復帰時と手動の再読み込みでも検査する。監視の開始・実行に失敗した場合は通知する。

## 6. アプリ終了中の移動への追従

前回のパス、種類、ファイル識別情報、内容ハッシュを`.lamina/tracking.json`に保存する。これは移動前との対応記録であり、検索索引とは分ける。

Windowsで取得できる場合はGetFileInformationByHandleのボリューム番号・ファイルインデックス・作成時刻を照合する。フォルダーにも同じ方法を使う。OSが提供する識別情報を利用するもので、MarkdownへIDを埋め込まない。

起動時は、まず同一パスの現存確認、次に移動したテーマフォルダの対応、その後に個別ファイルの対応を確認する。同名の月次ファイルをファイル名だけで一致させない。アプリ自身の置換保存後は追跡情報を更新する。

対応するのは、旧パスが消え、新しいパスが出現し、末尾の名前と種類が変わらない移動に限る。識別情報が一致する候補が一意なら対応させ、それで決まらない場合は同名・同内容ハッシュ（テーマは月次ファイル名と内容の構成）が一意な候補だけを対応させる。フォルダー移動の配下も同じ対応で更新する。曖昧なコピーを推測で結び直さない。別ドライブ・同期による置換は一意な内容照合で決まる範囲のみ対応し、あらゆる同期方式での追従を保証するものではない。

終了中の名前変更は、識別できても必須対応に広げず、リンク切れを許容するという仕様を維持する。

## 7. Markdown、リンク、YAML

Markdownを解析して参照先・見出し・位置を抽出し、変更時は必要な位置だけを書き換える。コードブロック内や単なる本文の文字列をリンクとして置換しない。参照形式リンク、エスケープ、空白、日本語、括弧を含むリンクも対象にする。

ノートリンクは短い名前が一意なら短縮表示できるが、保存上の曖昧さはパスで解消する。テーマ全体はテーマフォルダ、テーマ内日付は年月に対応した月次ファイルと見出しへ解決する。同名ノートの許可を制約変更で解消するのではなく、パス付き候補を提示する。

現在は`[[`の補完を実装し、Enterで確定、テーマをTabで途中補完した後の`#`で日付候補を表示する。未作成リンクからは確認モーダルでメモを作成できる。通常の相対Markdownリンクは参照元フォルダー基準とし、見つからないときに別フォルダーの同名メモへ接続しない。改名時はWikilinkの参照先と通常のファイル名表示を更新し、明示した別名・独自ラベルは保持する。通常リンク・参照形式リンクのURL、エスケープと文字参照を解析し、コード・HTML・画像内は置換対象にしない。

クリックで現在のタブへ移動し、ピン留め元なら新規タブにする。Ctrlクリック・ホイールクリックは新規タブ、Ctrl+Altクリックは右ペイン。編集中の記法ではCtrlクリックを使う。選択部分の切り出しは新規ファイルと元のリンク置換を同じ回復可能な操作に含め、元の本文へ戻る。

左のメモツリーはPointer Eventsでアプリ内のドラッグを処理し、同じ保管庫内のフォルダーへ移動する。6px以上の移動からドラッグを開始し、元パスと保管庫を一時状態に保持する。OSのファイルドロップとは別経路とし、WebView2のネイティブDrag and Dropへ依存しない。閉じたフォルダーは650msのホバーで展開する。移動先の強調・移動中の名前・平置きへ戻す領域をドラッグ中だけ表示し、開始時に既存行の位置を変えない。一覧の上下端で自動スクロールし、Escape・フォーカス喪失・ポインター取消で中断する。ドロップ後のクリックによる誤移動も抑止する。UIで同名衝突・自己配下への移動を抑止し、確定時も最新の走査結果で存在を照合する。処理は既存の回復可能な移動・リンク更新へ統合し、未保存本文の保存、画像パスの更新、タブとピン留めの追従を共通化する。フォルダー内の新規メモは上書きを許さない空ファイルとして作成して開き、メモ名にパス区切りを許さない。子フォルダー作成も保管庫内のWindows向けパス検証と操作記録を通す。

元のMarkdownテキストを正本にするため、通常の本文保存で構文木から全文を再生成しない。日付見出しをコード内や引用内から誤検出しない。

資料のYAMLはDocument APIで必要なキーを変更し、不明な追加項目とコメントを可能な範囲で保持する。`added`は引用した日付文字列、`themes`は文字列配列として保存する。未知の型や壊れたYAMLを黙って初期値に置き換えて保存しない。[yamlの公式資料](https://eemeli.org/yaml/)

資料の`path`は人が扱う元のパス／URLを保持し、本文のリンクはMarkdown向けに正しくエンコードする。Windowsパス、UNC、file URIの相互変換を共通関数にし、`#`、`%`、空白、日本語を含むファイル名で往復確認する。保存用表現と照合用のキーを分け、ユーザーが入力したSharePointのクエリを削らない。

## 8. 資料データベース

### 正本と登録

正本は`資料/`のMarkdown。現在は保管庫の走査結果と未保存バッファから資料・参照索引をメモリーに構築する。SQLiteへの永続化は後続の最適化であり、資料の正本にはしない。既存と同じパス／URLなら既存ページを読み、登録済みとして表示する。

貼り付けから確定までの情報はモーダルの編集状態として保持する。挿入先の物理ファイル・範囲・元の本文を記録し、確定時に未保存の編集を保存して最新状態を再照合する。資料ページと本文リンクを既存の操作記録へまとめて保存し、キャンセルなら両方を変更しない。確定後はCodeMirrorの履歴にも挿入1件として反映する。コード・HTML内への貼り付けは通常のテキスト入力を維持する。

本文のUndoではリンク挿入を取り消せる。確定後の本文Undoだけでは資料ページを自動削除しない。資料ページの本文は編集画面ではYAMLから分離し、本文の位置を元ファイルのオフセットへ戻して保存する。不正なYAMLは原文の編集画面で修復可能とし、既定値で上書きしない。`yaml`のDocument APIを使い、不明なキーとコメント、BOM・改行形式を保持する。

Windowsパス・UNC・file URIを照合用のキーへ正規化し、種類とファイル名の初期値を取得する。本文のリンクはエンコード済みfile URI、YAMLのpathは人が扱うパスとする。SharePointはURLのクエリ・フラグメントを保持し、異なるURLをファイル名で推測して統合しない。通常の資料リンクと情報ボタンは別の操作とし、後者は本文の右サイドバーへ一覧と共通のMaterialDetailを開く。ペイン・元ノート・資料のパスで対象を保持し、ノートが切り替わった場合は通常のサイドバーへ戻る。詳細内の「プロパティ」から編集モーダルを開く。

Windowsのコピー形式はCF_UNICODETEXT・CF_HDROP・FileNameWと、WebView2のHTMLリンク情報から取得する。OSからのファイルドロップはTauriのパス付きイベントで本文の位置へ振り分けるため、ウィンドウのdragDropEnabledを有効にする。画像もこの経路で元ファイルを読み込み、従来のPNG正規化・注釈保存へ渡す。資料は1件ずつ登録し、資料本体を保管庫へコピーしない。ネイティブ側でもパス・URLを検証して既定アプリへ渡す。実行形式や任意のURIスキームは資料として起動しない。

### テーマ

プロパティのテーマ名は既存テーマの候補から複数選択する。空配列を許容し、他のエディタで書かれた未知の名前も読み込み時に破棄しない。

テーマ内で貼り付ける場合は既存指定に今回のテーマを加え、確定時に保存する。テーマ名変更はノートリンクと資料`themes`の対応を同じ変更計画に含める。テーマ削除時は、残った指定を自動で消すか保持するかを操作設計で確認する。

一覧では1つのテーマを含む資料、またはテーマ未指定を絞り込める。テーマを含むすべての基本プロパティで並べ替えられる。複数のテーマを条件としてAND／ORで組み合わせるフィルタは後続候補とする。

### 修正とマージ

パス修正は、索引と編集バッファの双方から参照元を集める。表示名の明示的な変更を伴わない限り、パスだけの変更でユーザーが付けたリンク表示名を変更しない。

マージは残す資料とパスを決め、短いメモとMarkdown本文をそれぞれ確認して保持・統合する。テーマは和集合を初期値にし、追加日をどちらにするかを確認可能にする。リンク修正は変更プレビューを作成し、各ファイルのリビジョンを照合して適用する。

初期値は異なるメモ・本文の両方と早い方の追加日を保持し、確定前に編集できる。統合元の追加プロパティは本文のYAMLコードブロックへも残す。元資料への通常リンクだけでなく、統合元の資料ページへのノートリンクも残すページへ更新する。資料ページ2件を開いていた場合はタブを集約する。統合元の削除は資料ページだけに限定し、変更前の全文を操作記録に残して他の変更とまとめて適用する。途中終了では削除したページも復元し、外部で変更されていた場合は上書きせず停止する。以前の文字列形式の操作記録も引き続き読める。

参照元のない資料も登録情報として保持する。旧パスの別名一覧や履歴による恒久的な同一資料管理は導入しない。操作回復用の一時記録とは区別する。

## 9. 画像と注釈

現在は`添付/<時刻・プロセス・カウンター>/`の下に`original.png`、`annotation.json`、`rendered.png`を置く。静止画像はブラウザーでPNGへ正規化し、ピクセル寸法を保持する。新規取り込みは非表示の一時ディレクトリーへ3ファイルを書いてから公開し、完了してから本文へリンクを挿入する。既存画像の注釈・表示用PNG更新は`.lamina/image-operation.json`へ変更前後を記録し、中断時は元へ戻す。回復対象が外部で変更された場合は上書きせず止める。

注釈JSONは形式バージョン、元画像の寸法、図形の種類・座標・色・線幅・文字を持つアプリ用の構造にする。Konvaの内部オブジェクト全体の保存形式へ依存させない。座標は元画像のピクセルに揃え、ズーム倍率やWindowsの表示倍率を保存座標へ混ぜない。

丸・四角・テキストの選択と変形にはKonvaのTransformerを使い、文字入力はキャンバス上にHTMLのtextareaを重ねる。日本語変換確定とモーダル完了を混同しない。[Transformer](https://konvajs.org/docs/react/Transformer.html)、[テキスト編集](https://konvajs.org/docs/sandbox/Editable_Text.html)

矢印・直線にはTransformerを付けず、画像座標の両端に専用ハンドルを描く。ハンドルの画面上の大きさと当たり判定はズームにかかわらず保つ。回転付きの既存データも両端を画像座標へ変換して扱い、片端を動かしたら反対側を固定して開始位置とベクトルを保存する。保存形式バージョン1は維持し、PNG出力にも同じ形状を使う。ドラッグ中は作業用プレビューのみを更新し、離した時点で履歴を1件追加する。長さがなくなる変更は適用せず、端点が交差する向き・水平・垂直も扱う。

注釈編集中は作業用の履歴を持ち、「完了」でJSONと合成画像を保存する。「キャンセル」では元データを維持する。履歴はドラッグの各フレームではなく、操作完了を単位にする。

本文中の画像サイズは配置ごとの情報とし、標準HTMLの`<img src="相対パス" alt="説明" width="640">`で保存する。表示時の幅は本文領域に収め、自然な縦横比を保つ。通常のMarkdown画像と参照形式も表示し、サイズ変更時は同じHTML形式へ変換する。ノート移動時は画像の相対パスも更新する。画像記法は専用ボタンと範囲選択から編集可能。貼り付け・サイズ変更はそれぞれ独立したUndo操作にする。注釈を更新すると表示キャッシュを破棄して左右の画像を更新する。同じ画像の注釈更新によるPDFの再出力はM5で追加する。

画像の読み込みは保管庫内のパスに限定し、外部URL・保管庫外への参照は表示しない。任意のHTML属性・イベントはDOMへ引き継がない。SVGは実行しない。PNG／JPEG／GIF／WebP／BMPはWebView2で読み、取り込む際は静止PNGにする。1画像32MB・4,000万画素、注釈2,000個・JSON2MBを上限とする。元画像の内容・注釈・PNGのリビジョンを確認して更新し、古い編集結果を保存しない。

## 10. 検索とバックリンク

M2ではメモリー上に保管庫全体の対象とファイル本文を索引化し、開いている編集バッファを重ねる。`Ctrl+Shift+F`で日本語を含む部分一致を検索し、テーマ名・日付・行・抜粋を表示して該当位置へ移動する。右のバックリンクには参照行の前後1行と参照先の日付・見出し区分を表示する。資料一覧ではタイトル・メモ・パス・テーマを検索でき、全文検索でも資料のMarkdownを扱う。SQLiteへの永続化は未実装。以下はその後の拡張方針。

SQLite索引にはノート、日付見出し、資料、参照関係、画像依存関係を格納する。参照元は物理ファイルの位置と論理テーマの対応を持ち、該当月・日付・行へ移動できるようにする。

日本語の部分一致を必要とするため、単語分割に依存しない検索を基本にする。FTS5 trigramは3文字以上の絞り込み候補とし、1～2文字は別の部分一致検索へ切り替える。短い検索語を検索不能にしない。SQLite公式資料でもtrigramの全文検索は3文字未満では一致しないため、代替処理が必要。[SQLite FTS5](https://www.sqlite.org/fts5.html)

検索対象は本文と資料のプロパティ。`.lamina/`や画像バイナリは対象外とする。短い入力の連続処理は取り消し可能にし、古い検索結果を新しい条件の結果として表示しない。

保存後に索引を更新するまでの間は、開いている編集バッファの結果を重ねて、変更したばかりの参照先と抜粋の不一致を抑える。日付のない通常メモには日付を捏造しない。

## 11. 自動PDF出力

### 生成方式

印刷用HTMLを非表示のWebView2へ表示し、フォント・画像・数式の準備完了を確認してからPrintToPdfを呼ぶ。編集画面を撮影してPDFにする方式は使わず、本文をテキストとして出力する。印刷用CSSはA4縦、読みやすい明るい用紙色、ページ番号、改ページを定義する。

WindowsのWebView2はサイレントなPDF生成APIを持つ。Tauriからプラットフォーム固有WebViewへアクセスする経路は存在するが、両者の接続と非表示レンダリングは実装検証が必要。通常の`window.print()`による印刷ダイアログでは自動出力要件を満たさない。[WebView2の印刷機能](https://learn.microsoft.com/en-us/microsoft-edge/webview2/how-to/print)、[Tauri with_webview](https://docs.rs/tauri/latest/tauri/webview/struct.Webview.html)

ネイティブWebViewの型との互換性を維持するため、Tauriと関連するWebView2バインディングは互換性の確認できた組み合わせに固定する。Tauri側もネイティブアクセス時のバージョン固定を推奨している。[公式APIの注意](https://docs.rs/tauri/latest/tauri/webview/struct.Webview.html)

### 更新判定とキュー

- 対象ファイルごとに、本文、表示タイトル、参照画像、注釈入り画像、印刷テンプレートの版を含めた出力用ハッシュを計算する。
- 前回成功したハッシュを`.lamina/export-state.json`に保持する。失敗や中断を成功として記録しない。
- 画像・注釈を更新した場合は、画像依存関係から関係する月次ファイルと通常メモを更新対象にする。
- タイマーはアプリ起動から1時間間隔を初期案とし、出力中の再要求は重複実行せずキューへまとめる。
- PDF生成は1件ずつ処理し、出力中も本文編集を続けられるようにする。
- 書き出し中に本文が変わっても、出力開始時のスナップショットの成功だけを記録する。以後の変更は次回の更新対象に残す。
- PDFも一時ファイルへ作り、成功後に正式な出力先へ置換する。

WebView2では同時に複数の印刷処理を実行できず、完了前にアプリが終了すると保存できない。そのため直列化と終了待機が必要。[PrintToPdf API](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2_7)

### 終了処理

通常終了の要求を一度保留し、編集バッファの保存、変更対象PDFの生成、管理情報保存の順に完了させて終了する。終了処理中の二重実行を防ぐ。

失敗時だけ、対象と再試行の選択肢を表示する。PDFを今回生成せずに終了する場合も、未出力状態を残して次回に再試行できるようにする。強制終了やOSの強制終了は通常終了と分け、未完了処理は次回起動時に回復する。

出力ファイルの移動・削除に伴う既存PDFの整理、資料ページ自体のPDF出力、外部資料への到達性は、仕様書に残る確認項目とする。

## 12. 管理ファイル案

```text
.lamina/
  config.json         # 保管庫と出力の設定
  workspace.json      # タブ・ピン留め・分割・選択とスクロール
  tracking.json       # 前回のファイル対応。移動検出に利用
  export-state.json   # PDFの前回成功ハッシュ
  index.sqlite        # 再構築可能な検索・バックリンク索引
  operations/         # 複数ファイル操作の回復用記録
```

管理ファイルは形式バージョンを持たせる。索引を作り直してもノートと資料ページは失わないが、追跡情報を削除すると削除前のパスとの対応は復元できない場合がある。すべてを単なるキャッシュとして同列に扱わない。

## 14. 先に検証する条件

1. WebView2上で、日本語変換中のライブプレビューとUndoが安定する。
2. 月境界をまたぐ編集と左右同時表示で、保存先と本文が食い違わない。
3. Konvaの日本語テキスト入力が、モーダルの完了操作やフォーカス復帰と干渉しない。
4. 非表示WebViewからダイアログなしで、検索可能な日本語PDFと注釈入り画像を生成できる。
5. パスコピー・UNC・SharePointリンクを、別エディタでも読めるMarkdownへ往復変換できる。
6. 終了中のフォルダ移動を、複数の同名月次ファイルがあっても誤接続せず検出できる。

これらは実装済みという意味ではない。実装開始後の最初のマイルストーンで実機検証し、その結果を踏まえて本設計を更新する。
