# Lamina.md

Windows向けの個人用Markdownエディタ。技術開発のテーマ別記録、再編集可能な画像注釈、Markdownで保存する資料データベース、自動PDF出力を中心に設計している。

正式名称は**Lamina.md**（ラミナ）。コード上の名前は`lamina-md`、保管庫内のアプリ管理フォルダーは`.lamina/`。

## Windowsへのインストール

[GitHub Releases](https://github.com/yuma1nu/Lamina-md/releases)から`Lamina.md_0.1.1_x64-setup.exe`をダウンロードして実行する。Windows x64向けで、現在のユーザーにインストールする。インストーラーは日本語・英語に対応し、WebView2が未導入の場合はダウンロードするためインターネット接続が必要。

初期開発版 v0.1.1。インストーラーはコード署名していないため、Windowsの保護機能によって確認が表示される場合がある。実装済みの機能と未実装・未確認の項目は以下を参照。

2026-11-12に初期実装へ着手した。日々の編集基盤、ノートリンク・検索・移動追従、画像表示・注釈編集に加え、資料リンクの登録・一覧・参照元・パス修正・統合を実装した。自動PDFなど、初期版全体は開発中。

## 現在の実装

- ダークモードを前提とした実アプリの外枠、テーマ・メモ一覧、新規作成フォーム。
- CodeMirrorによる本文編集、見出し・太字・斜体・インラインコード・引用・コードブロック・リンクのライブプレビュー。
- 編集中の行ではMarkdown記法を表示し、コードブロック内ではフェンスも編集できる。装飾の入れ子、エスケープ、参照形式のリンクにも対応。
- 箇条書きの`-`・`+`・`*`は編集中も「•」で表示し、保存するMarkdownは保持する。字下げ・行頭記号の中へキャレットを入れず、Homeやクリックも本文先頭へ寄せる。本文先頭での左キーは前の行末へ戻る。
- 折り返しの境界を含むキャレットはCodeMirrorで描画し、上下移動の目標列を保持する。全選択・コピーでは元の字下げとMarkdown記法も含められる。
- HTTP／HTTPSのリンクは既定のブラウザーで開く。プレビューではクリック、編集中の行では`Ctrl+クリック`、どちらもホイールクリックに対応。
- リストの`Tab`は直前の兄弟項目を親にできる場合だけ1段字下げし、親のない段飛ばしを防ぐ。子孫・継続文・選択項目をまとめて移動し、`Shift+Tab`と本文先頭のBackspaceで1段戻す。各操作をUndoできる。
- リストのEnterで項目を継続し、空の子項目は1段戻り、最上位の空項目で終了する。`Shift+Enter`は同じ項目内の改行。通常本文・コードのTabは4スペース単位の字下げを維持する。
- 月次ファイルを一続きに編集するモデル、月境界を保存データに混ぜない変更処理、今日の見出しと月次ファイルの生成。
- タブ、ピン留め、左右分割、同じ文書を開いたペイン間の同期。
- 右ペインの最後のタブを閉じると、保存後に右ペインを畳んで左本文へフォーカスを戻す。別のタブが残る場合や保存に失敗した場合は右ペインを保持する。
- 前回の保管庫の自動再開、タブ・ピン留め・分割・左右それぞれの選択位置とスクロール位置の復元。
- サイドバー・目次の表示状態の復元、タブを切り替えたときの編集位置の保持。
- 500ms後の自動保存と`Ctrl+S`、保存キュー、失敗時の編集保持・再試行。
- 通常終了時は本文と画面状態の保存完了を待ち、失敗すれば編集可能な状態へ戻して終了を止める。
- Tauri側の保管庫作成・走査・読み込み・保存・外部変更の照合コード。
- UTF-8 BOMと一般的なCRLF／LFを編集モデルから分離し、保存時に復元。
- `[[`によるノート候補・新規メモ作成、テーマ全体と日付へのリンク、周辺文章付きバックリンク。
- 保管庫全体の本文検索、結果の日付・行への移動、選択部分を別メモに切り出して元にリンクを残す操作。
- メモフォルダーの作成、ノート・テーマ・フォルダーの名前変更と移動、参照元リンクの一括更新。明示した別名やコード内の文字列は保持。
- 左メニューでメモやフォルダーをドラッグして整理できる。フォルダー行の追加ボタンから直接メモを作り、「…」から子フォルダーも作成できる。
- 起動中のファイル変更の監視、終了中の同名ファイル・テーマフォルダー移動の検出。移動したタブと編集位置も復元。
- 移動・リンク修正・切り出しの操作記録と、途中終了後の回復。外部編集や同名ファイルを無条件に上書きしない。
- クリップボード画像・画像ファイルのドロップ、本文中での表示と比率を保つマウスサイズ変更、表示幅の保存。
- ダブルクリックで開く注釈モーダル。丸・四角・矢印・直線・日本語テキストの追加、選択・移動・サイズ変更・削除、色・線幅・文字サイズ、ズーム、Undo／Redo。
- 矢印・直線は選択すると両端のハンドルが現れ、片端を直接ドラッグして長さと向きを変えられる。反対側は固定し、以前の回転付き注釈も再編集できる。線全体のドラッグ移動にも対応する。
- 元画像・注釈JSON・表示用PNGを分けて保存し、再起動後も再編集できる。キャンセルと保存失敗では既存画像を保持し、保存の途中終了は回復する。
- パス・URLの貼り付けで資料登録モーダルを開き、資料ページと本文の通常リンクをまとめて保存。登録済みの判定、追加日の保持、テーマの自動追加、種類別アイコン、情報ボタンからの再編集。
- 資料一覧タブで種類・テーマ・追加日のフィルタ、検索、プロパティによる並べ替えと一覧内編集。右の詳細にはメモ全文と日付・周辺文章付き参照元を表示し、該当位置へ戻れる。
- 資料ページの詳しい説明をMarkdownで編集。YAMLの6プロパティ・未知のキー・コメントと本文を分けて保持し、不正なページは一覧から修正できる。
- パス修正と2件の統合で、参照元のリンクだけを一括修正。メモ・詳細本文・テーマを確認して統合し、途中終了から回復できる。

Windowsの実アプリで、保管庫を開く、日本語を追記する、自動保存する、通常終了する、再起動でタブ・ピン留め・分割・左右の表示位置へ戻る流れを確認済み。日本語IMEの変換操作、数式・表の表示、コード内の言語別ハイライト、自動PDFは後続の実装対象。資料のOS連携は実機確認を残している。本文のHTMLは実行せず、画像タグの既知の属性だけを使って画像表示を組み立てる。

月をまたいだ表示でも、プレビューとEnter／BackspaceのMarkdown補完は物理ファイルごとに処理する。前月でコードフェンスを閉じ忘れても、翌月の表示やリストの改行補完へ持ち越さない。表示切り替えだけでは元のMarkdownを書き換えない。

基本のライブプレビューはWindowsのWebView2でも目視確認し、コードのラベルからフェンスの編集へ戻る操作、日本語追記後のMarkdown保持、Webリンクから既定のEdgeに検証用ページが開くことを確認した。

ノートリンクもWindows実機で確認済み。本文とバックリンクでの往復、改名時の実ファイル・参照元更新と別名・コードの保持、終了中の移動後のリンク修正・タブ復元、起動中の外部移動の自動反映を確認した。

左メニューのフォルダー内への直接作成、メモのドラッグ移動、移動後の実ファイル・参照リンク・タブの追従もWindows実機で確認済み。

画像はWindows実機で表示、丸の追加・移動・サイズ変更、日本語注釈の保存、再起動後の個別再編集を確認済み。ペイントから実クリップボード経由の画像貼り付けも確認した。OSからの実ファイルドロップと表示倍率の網羅的な検証は残る。

画面状態は保管庫内の`.lamina/workspace.json`に保存する。本文へ管理用IDを書き込まない。復元できないタブは知らせ、残りを復元する。破損・未対応の画面状態を保存し直す場合は、元の管理ファイルを`workspace-recovered-*.json`として退避する。

## ノートをつなぐ操作

- `[[`で保管庫内の候補を表示し、Enterで挿入する。テーマ名をTabで補完して`#`を入力すると、そのテーマの日付を選べる。同名ノートはパスで区別する。
- プレビューのリンクはクリックで移動する。ピン留め元からは別タブで開き、Ctrlクリック・ホイールクリックは新規タブ、Ctrl+Altクリックは右ペインで開く。記法を編集中の行ではCtrlクリックを使う。
- 右側のバックリンクから参照元の周辺文章・日付・行を確認して戻れる。目次へ切り替えると、テーマ・通常メモ・資料ページの本文のH1〜H6とSetext見出しを階層付きで表示する。見出しのクリックでその位置へ移動し、編集も即時反映する。コード・YAML・引用やリスト内の見出しは含めない。
- `Ctrl+Shift+F`で本文を検索する。選択部分は上部のはさみボタンからメモへ切り出す。
- 名前変更・移動は項目や本文タイトル横の「…」から行う。終了中の名前変更は追従対象外。同名・同内容の候補が複数ある移動は推測で結び直さない。
- メモは左メニューのフォルダー行へドラッグして移動する。ドラッグ中に一覧の下へ現れる「メモ直下に移動」で平置きへ戻せる。閉じたフォルダーに重ねて待つと展開する。
- フォルダー行にマウスを重ねるとメモ追加ボタンが現れ、その配下へ直接作成できる。「…」にはメモ追加・子フォルダー作成もある。移動時は未保存の本文を保存し、参照リンク・画像の相対パス・タブを更新する。同名への上書きや、自分自身の配下への移動はしない。

移動の対応記録は`.lamina/tracking.json`、操作の回復記録は`.lamina/operations/current.json`へ保存する。Markdownへの識別IDの追加は不要。検索と参照索引は現在メモリー上で再構築し、未保存の本文も反映する。

## 画像を使う操作

画像の貼り付けまたはファイルのドロップで保管庫へ取り込む。本文の画像をクリックすると左右下のサイズハンドルが使え、ダブルクリックまたは「注釈を編集」でモーダルが開く。図形ツールはキャンバス上のドラッグ、テキストは配置位置をクリックして入力する。文字の確定はボタンまたは`Ctrl+Enter`。選択した注釈はドラッグ・角のハンドル・Deleteで操作できる。テキストの再編集はダブルクリック。「完了」で保存して本文へ戻り、「キャンセル」では今回の変更を破棄する。

静止画像は元のピクセル寸法でPNGへ正規化し、`添付/<時刻と衝突回避文字列>/original.png`・`annotation.json`・`rendered.png`へ保存する。本文は`<img src="相対パス/rendered.png" alt="説明" width="640">`の標準HTMLを参照する。幅を変えても画像ファイルの解像度は変えない。通常のMarkdown画像や既存の画像タグも読み込み、注釈を付けるときは元ファイルを上書きせず専用の添付へコピーする。

上限は1画像32MB・4,000万画素、注釈2,000個。貼り付けのUndoで添付を自動削除せず、Redoや別ノートの参照に備えて保持する。画像を含むメモを移動すると、画像の相対パスも更新する。注釈JSONとPNGの更新途中の回復記録は`.lamina/image-operation.json`に保存する。注釈を編集中の通常終了は止め、完了・キャンセルを促す。PDFへの反映はPDF機能の実装時に追加する。

## 資料を使う操作

本文の通常の入力位置に、引用符付きのWindowsパス、共有パス、SharePointのコピーURLを貼り付ける。モーダルの内容を確認して「登録して挿入」を押す。元の資料はコピーしない。本文には標準のMarkdownリンクを保存し、パスの空白・日本語・`#`・`%`などはfile URIで表す。SharePointのクエリは保持し、認証やMicrosoft Graphへの連携は行わない。

本文の資料名と種類アイコンは資料本体を開く。隣の情報ボタンはプロパティを開く。通常のMarkdown記法を編集している行ではCtrlクリックでリンクを開く。画像と資料のOSドロップはTauriのパス付きイベントを使い、資料は1件ずつ登録する。コピーしたファイルの貼り付けではCF_HDROP・FileNameW、URLではHTMLのファイル名情報も読み取る。

左の「資料一覧」を開き、資料名をクリックすると右に詳細を表示する。資料名はダブルクリックまたはF2、ほかのプロパティはセル内で編集し、Enterまたはフォーカス移動で保存する。Escapeは取り消し。テーマ欄はカンマ区切りで複数指定できる。資料名の隣の矢印は資料本体を開く。「資料ページ・詳しい説明を開く」で、プロパティを崩さず本文を編集できる。

パスの修正では参照元の件数と抜粋を確認できる。統合では一覧で2件を選び、残すパス、メモと詳しい説明を確認して保存する。初期値はメモ・本文を両方保持し、テーマは和集合、追加日は早い方。未知の追加プロパティを持つ統合元は、その内容も本文へ残す。本文のUndoは挿入したリンクだけを取り消し、登録済み資料は保持する。

資料機能はブラウザの操作・Rustの保存回復テストで検証済み。Windows実アプリの最終操作確認は、検証用ウィンドウを自動操作ツールが前面化できないため保留している。実クリップボード、OSからのドロップ、既定アプリの起動、SharePoint／ファイルサーバへの実到達は未確認。

## 開発環境

Windowsでのデスクトップ起動にはNode.js、RustのMSVCツールチェーン、Visual Studio C++ Build ToolsとWindows SDK、WebView2が必要。[Tauriの前提環境](https://v2.tauri.app/start/prerequisites/)

複数のVisual Studioが存在するこのPCでは、PowerShellで次を実行してVS 2022の開発環境を読み込む。現在のシェルだけに反映され、システム設定は変更しない。

```powershell
. .\scripts\enable-windows-build.ps1
```

```powershell
npm ci
npm run tauri -- dev
```

ブラウザでフロントエンドを確認する場合は`npm run dev`。ブラウザ単体では保管庫操作はできず、サンプル保管庫へ自動的に切り替える機能もない。

Node.jsだけがありnpmがない環境向けに、公式レジストリからプロジェクト内へnpmを取得する補助スクリプトを用意している。

```powershell
node scripts/bootstrap-npm.mjs
node .tools/npm/bin/npm-cli.js ci --cache .tools/npm-cache
node .tools/npm/bin/npm-cli.js run tauri -- dev
```

## 検証

```powershell
npm run build
npm test
npx playwright install chromium
npm run test:browser
```

ブラウザテストは、テストコード内だけでTauri IPCを置き換えてフロントエンドを検証する。Rustのファイル操作やWindows WebView2の動作を検証するE2Eではない。

ネイティブ側の検証・ビルドは、上記の開発環境を読み込んだPowerShellで実行する。

```powershell
cargo test --locked --manifest-path src-tauri/Cargo.toml
npm run tauri -- build -- --locked
```

2026-11-13時点ではフロントエンドの型検査・本番ビルド、単体テスト65件、ブラウザ操作テスト69件が通過。編集・保存・リンク・画像・注釈、箇条書きの上下移動と字下げ、右ペインの終了に加え、矢印・直線の端点編集、メモのドラッグ整理とフォルダー内作成を確認。回転付きの旧データ、反対側の固定、ズーム中の操作、Undo／Redo、キャンセル、保存・再起動後の再編集を含む。Rust 1.99.1／Cargo 1.99.1（stable-x86_64-pc-windows-msvc）をユーザープロファイルへ導入し、Rust依存関係を取得済み。WebView2も検出済み。

既存のVisual Studio 2022へMSVC x64/x86ビルドツールとWindows SDK 10.0.26100を追加済み。MSVC 14.44.35207のヘッダー・標準ライブラリを確認し、インストーラーは正常終了した。Windowsの再起動要求はない。

Windows上でRustテスト24件が通過。実ファイルの保存・追跡・移動・監視に加え、画像保存・再読込・古いリビジョンの拒否・注釈とPNGの途中更新からの復旧・外部変更の保護を含む。Tauriのリリースビルドも成功し、`src-tauri/target/release/lamina-md.exe`を更新済み。配布用NSISインストーラーは`src-tauri/target/release/bundle/nsis/Lamina.md_0.1.1_x64-setup.exe`へ生成する。実機の確認は専用の保管庫とWebView2プロフィールを使い、普段の保管庫・前回の保管庫設定とは分離して実施した。

追加対象は[scripts/windows-build.vsconfig](scripts/windows-build.vsconfig)に記録した。同じ構成が必要な別の開発PCでは、VS 2022のインストール後にPowerShellから`& .\scripts\install-cpp-tools.ps1`を実行できる。Windowsの管理者確認が必要で、インストーラーは自動再起動しない。

Rust依存関係は生成した`src-tauri/Cargo.lock`、npm側は`package-lock.json`で固定している。
